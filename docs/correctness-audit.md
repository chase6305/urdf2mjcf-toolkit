# 正确性检查记录

本次检查针对 MuJoCo 3.8.0、urdf2mjcf 0.2.39 和当前转换流水线，使用代码审查、最小反例、解析公式和实际 MuJoCo 编译验证。以下结论适用于已覆盖的转换行为，不代表任意机器人模型的仿真参数都已标定正确。

## 发现并修复的问题

| 严重程度 | 原问题及影响 | 修复与验证 |
| --- | --- | --- |
| 高 | 外部后端忽略惯量非对角项；原生导入后惯性坐标系旋转也可能丢失 | 将源惯量分解为等价主惯量，序列化后恢复完整惯性坐标系；对重建到 link 坐标系的张量作解析对比 |
| 高 | 外部转换器会删除根节点惯量，随后根据几何重新推断质量 | 从暂存 URDF 恢复每个有惯量的 link，包括根节点；固定及浮动基座均验证质量、质心和惯量 |
| 高 | 省略关节轴时外部后端使用 Z 轴，阻尼、摩擦及部分限位语义丢失 | 显式补齐 URDF 默认 X 轴，恢复动力学参数、连续关节无限位语义及正的 effort 上限 |
| 高 | 惯量重算忽略非均匀缩放、几何旋转、原惯性坐标系及同一 link 的其他几何体 | 在 link 坐标系内汇总所有选定几何体，以平行轴定理合成，再变换回惯性坐标系；使用长方体、圆柱、球和双组件解析公式验证 |
| 高 | 惯量检查仅检查坐标轴上的对角值；无法识别部分违反主惯量三角不等式的张量 | 改为检查特征值；拒绝非有限质量、非有限惯量及未封闭/非正体积网格，不再生成占位惯量 |
| 高 | 失败时旧 XML 保留，但其网格可能已被覆盖；再次加载会得到不同几何 | 每次运行在独立暂存目录转换资源，验证后发布；发布 I/O 异常时同时回滚资源和 XML，测试逐字节比较旧结果 |
| 高 | 不同包中的同名网格可能错误匹配本地暂存资源；同目录的同名 OBJ/STL 等可能互相替代 | 按实际源文件到暂存文件的映射解析，保留包身份；不同格式共用转换名称时明确报错 |
| 中 | GLB 不合并模式只导出 geometry 表，遗漏节点实例和变换；固定六位小数会压扁微小模型 | 按场景节点复制实例并应用变换，提升数字输出精度；验证实例数量、包围盒、质心和微小网格尺寸 |
| 中 | 编译通过仍可能包含无穷大的物理参数 | 发布前检查模型关键物理数组的有限性；无效模型不发布 |
| 中 | 不支持的 URDF 关节语义可能静默消失 | 当前明确拒绝 mimic、planar 和内部 floating 关节，检查模式也报告不支持项 |
| 高 | 单个 link 出错后的自动恢复会重算其他有效 link，覆盖已标定的惯量和质心 | 自动恢复仅修复无效定义；两种后端均用有效完整张量加无效组件的样例验证，报告记录修改的 link |
| 高 | 对角惯量省略零值非对角项时，原生导入器可能报错并触发不必要的几何重算 | 暂存时补齐零项；禁用惯量重算的双后端测试验证原质量、质心和惯量不变 |
| 中 | 只读检查会把零关节轴、非有限参数、无效主惯量和错误几何尺寸报告为通过 | 检查与转换共用物理参数校验，汇总带 link/joint/实例上下文的问题；速度约束未实现的提示单独使用 warning |
| 高 | 最终 XML 可能仍引用外部网格的绝对路径；源目录移动后输出无法加载 | 发布前收集最终文件依赖，外部文件按 SHA-256 与扩展名命名；双后端测试中移走源目录及原输出目录后，复制的输出仍可加载 |
| 高 | 显式纹理目录或绝对纹理路径可能被目录前缀规则和同名回退覆盖 | 先按上游编译器目录解析确切文件，再收集为相对路径；验证同名但颜色不同的纹理不会混用 |
| 中 | 原流程在编译后再次改写目录属性，校验的 XML 与发布内容不完全相同 | 暂存目录采用与最终输出相同的 XML/meshes 布局，使用相对路径编译，并逐字节验证编译内容与发布内容相同 |
| 高 | 非标准目录中的网格引用可以解析，却绕过格式转换；后端收到不支持的 GLB 等格式后失败 | 根据 URDF 引用补充转换 DAE、GLB、PLY、OFF、3MF，覆盖显式视觉和碰撞；相同源文件仅处理一次，自动后端回退复用结果 |
| 高 | 不同目录的同名源文件进入补充转换后可能争用资源名称 | 按实际源路径生成独立名称，并避开已有文件和目录；双后端验证两个同名 GLB 的不同几何尺寸 |
| 高 | URDF 将输出 meshes 目录中的文件当作输入时，发布会替换源文件 | 引用解析后拒绝源网格与输出资源目录重叠，测试确认被引用的文件保持不变 |
| 高 | 输入 URDF 自身位于输出 meshes 目录时，发布清理可能删除该 URDF | 初始化时按实际路径拒绝重叠，直接路径和符号链接均验证源文件不变且不创建转换资源 |
| 高 | 非有限正则化参数或有限参数的计算溢出可能将 NaN/Inf 惯量写回源文件 | 校验参数、计算阈值与正则化结果，并在写入前再次校验物理有效性；失败时源文件不变且不生成备份 |

## 数值验证范围

- 两种后端分别验证固定和浮动基座。
- 三关节链包含 revolute、prismatic、continuous，多个非零 origin 旋转，以及三个关节配置。
- 关节轴、上下限、阻尼、摩擦、effort 上限与源定义对比。
- 每个 link 的质量、质心和旋转后的完整惯量张量与解析值对比；张量绝对容差为 `2e-5`。
- 正向运动学和几何体世界坐标姿态与独立矩阵计算对比；绝对容差为 `2e-6`。该容差也覆盖原生 XML 序列化的几何姿态舍入。
- 重算惯量覆盖非均匀网格缩放、两个坐标系旋转、平行轴项、基本几何体及原始文件备份。
- 转换失败和发布失败均验证旧 XML、旧网格内容不变，并重新编译旧结果。
- 原有后端回退、批量转换、材质分片、资源路径与模型编译测试继续保留。
- 自动恢复验证零惯量及违反主惯量三角不等式的输入，只修改对应 link；未参与修复的完整惯量张量绝对容差为 `1e-10`，质心为 `1e-12`。恢复失败和禁用恢复均验证不会发布结果。
- 只读检查与转换对相同错误给出一致错误码；批量及单文件检查只有速度提示时均成功。`--only-invalid` 对全有效输入保持文件字节不变，也不创建备份。
- 资源迁移覆盖绝对路径、`file://`、`package://`、空格、外部碰撞网格、纹理、符号链接和父目录引用；移走源文件及原输出后，对比网格顶点、面、缩放、几何姿态、质量、惯量和纹理像素数组。
- 资源清单验证相对路径、字节数、SHA-256、引用关系及重复运行稳定性；复制失败验证旧输出逐字节不变。
- 两种后端分别覆盖非标准目录的 DAE、GLB、PLY、OFF、3MF；通过独立包围盒计算验证视觉/碰撞的位置和非均匀缩放，绝对容差为 `2e-6`，并验证重复运行及迁移后顶点不变。DAE 回归使用 trimesh/pycollada 回退。
- 外部 GLB 纹理像素与预期颜色直接比较；补充转换报告检查源文件、全部引用位置、状态与输出路径。损坏网格失败时保留旧 XML 和资源，自动后端回退不重复预处理。

主要测试位于 `tests/test_physics_correctness.py`、`tests/test_physical_validation.py`、`tests/test_urdf_inertia_calculator.py`、`tests/test_conversion_manager.py`、`tests/test_glb_to_obj_converter.py`、`tests/test_asset_bundle.py` 和 `tests/test_referenced_meshes.py`。

## 本次验证结果

- Python 3.12 环境下全套测试：**231 passed**。其他 Python 版本未在本次本地检查中运行。
- Ruff、Black（40 个 Python 文件）、字节码编译、依赖一致性和 `git diff --check` 均通过。
- wheel 和源码包构建成功；安装 wheel 后，在仓库外运行实际命令行，分别验证外部后端和自动回退到原生后端。
- 安装版样例的两种后端均得到总质量 `3.0`，旋转后的惯量张量最大绝对误差为 `2.7e-15`，关节轴、阻尼和摩擦与源定义一致。该误差仅对应此样例，不是任意模型的精度承诺。
- 安装版再次转换失败时，已有 XML 和网格逐字节保持不变。
- 安装版选择性恢复样例的两种后端均只修复 `invalid` link，总质量保持 `14`，有效 link 的惯量 `[2, 3, 4]` 和质心 `[0.1, 0.2, 0.3]` 不变。独立 `--only-invalid` 命令、原文件备份、重复运行不写文件及仅含 warning 的检查退出码也通过实际命令行验证。
- 安装版分别运行双后端单文件转换和原生后端两模型批量转换；移走输入目录及原输出后，四份复制输出均可编译，网格及物理数组完全一致，全部资源清单的大小和 SHA-256 与复制后的文件匹配。
- 新增补充预处理的安装版验证：非标准目录中两个同名 GLB 分别保留几何，单文件运行两种后端及自动回退，批量运行两个模型。五份输出均通过位置/缩放包围盒检查；移走输入及原输出后，复制结果全部可加载，网格与物理数组完全一致，资源清单校验值全部匹配。
- 提交前重新构建并安装 wheel，复验上述五份输出；另运行四项源文件保护命令行样例。输入 URDF 位于输出 meshes 目录、正则化参数为 Inf/NaN 及有限参数计算溢出时，均返回失败，源文件逐字节不变。

## 行为边界与仍需模型级验证的部分

- 转换支持 fixed、revolute、continuous 和 prismatic。机器人整体浮动使用 `--floating-base`；内部 floating、planar 和 mimic 尚未实现，现为显式失败。
- 默认后端仍会按原有策略调整根节点高度，并生成执行器、传感器；原生后端保留源坐标且不自动生成这些对象。两种输出的完整场景行为不要求相同。
- URDF 的 velocity 上限未自动变成速度约束；需要控制器实现。接触参数和自动添加的地面也应根据应用检查。
- 惯量重算假设选定组件为均匀密度实体，按体积分配既有总质量；组件重叠会重复计入体积。此流程不能推断真实材料分布、空腔或负载。已有质量始终保留，密度参数不会重新定义质量。
- 视觉和碰撞几何只选择一种：优先指定类别，其完全不存在时才使用另一类，避免把两类表示重复计入惯量。缺少惯量定义的 link 不自动生成质量；选择性修复时，无效惯量缺少可用几何会失败。独立命令的全量重算仍跳过缺少惯量或几何的 link。
- 选择性修复依据源定义的有限性、正定性及主惯量三角不等式，不会为了通过其他编译器限制而重算数值有效的已标定惯量。质量和惯量均为零的静态坐标帧允许通过输入检查，其是否能作为运动部件由 MuJoCo 编译判断。
- 自动粗略碰撞补全仍依赖文件名和视觉网格匹配；没有证明它与 CAD 碰撞外形及接触行为等价。需要可靠碰撞模型时，应在 URDF 中显式定义 collision 并进行接触测试。
- 暂存发布支持普通转换错误及 I/O 异常的回滚；没有宣称两个文件系统重命名操作构成断电安全的原子事务。同一输出目录应由一个转换任务独占；批量命令已为模型分配独立目录。
- 补充预处理覆盖可在本地解析的 DAE、GLB、PLY、OFF、3MF 引用；不下载远程网格，也不扩展其他格式支持。独立源路径使用不同生成名称，既有常规目录中的转换名称冲突仍会明确失败。
- 资源收集针对最终 MJCF 的运行文件依赖，不是对源工程全部 MTL/PBR 文件或中间 XML 的完整归档。未覆盖所有 DAE 单位/坐标系、复杂材质表现及真实机器人长期动态仿真。

## 对照依据

URDF 的惯性原点同时定义质心位置和惯性坐标系，相对于 link 表达，见 [ROS 的物理属性说明](https://docs.ros.org/en/humble/Tutorials/URDF/Adding-Physical-and-Collision-Properties-to-a-URDF-Model.html)。MuJoCo 的惯性坐标系采用主惯量轴，完整张量由编译器作特征分解，见 [MuJoCo 3.8 惯量与关节定义](https://mujoco.readthedocs.io/en/3.8.0/XMLreference.html#body-inertial)。网格质量属性计算依赖均匀密度和封闭实体条件，见 [Trimesh mass_properties](https://trimesh.org/trimesh.html#trimesh.Trimesh.mass_properties)。具体导入器偏差以上述固定版本的本地数值复现为依据。

资源路径处理与隐式命名对照 [MuJoCo compiler 目录规则](https://mujoco.readthedocs.io/en/3.8.0/XMLreference.html#compiler-meshdir)、[mesh 命名](https://mujoco.readthedocs.io/en/3.8.0/XMLreference.html#asset-mesh)及 [texture 文件属性](https://mujoco.readthedocs.io/en/3.8.0/XMLreference.html#asset-texture)。
